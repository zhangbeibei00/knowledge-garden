# 激活量化：动态 vs 静态

## 为什么激活量化是个难题

权重量化好办——训练完了权重就固定了，可以离线慢慢算。

激活值不一样：**它随着每次输入而变**。同一个模型跑不同 prompt，各层激活的数值范围可能差好几倍。核心难点就是——**scale 什么时候算？**

答案分两派：**静态**（提前算好）和**动态**（推理时实时算）。

## 静态激活量化

**核心思路**：跑少量数据当"校准集"，提前把每层激活的 scale/zero_point 算好，写死到模型里。

### 完整流程

**步骤 1：模型准备**

将训练好的 FP32 模型插入**量化观察节点**（observer），此时模型不进行实际量化，只统计数值范围。

**步骤 2：校准（Calibration）**

选取 500~1000 条典型输入数据喂给模型。模型推理过程中，observer 记录每一层激活的 min/max（或走 KL/MSE 等高级校准算法），最终计算出**固定的** scale 和 zero_point。

**步骤 3：量化导出**

校准完成后，将 scale/zero_point **写入模型配置**。推理时直接使用这些固定参数进行量化计算。

### 优缺点

- ✅ **推理无额外计算，速度最快**
- ✅ 部署最简单，硬件调度可预测
- ❌ 对分布变化大的输入（文本、图像差异大）**精度掉得明显**
- ❌ 校准数据代表性不足时容易翻车

**适用场景**：延迟敏感、输入分布相对稳定（如固定业务场景的图像分类、语音识别）。

## 动态激活量化

**核心思路**：不校准，推理时每一层实时计算当前 batch 数据的 min/max，动态生成 scale。

### 流程

无校准步骤。推理时，每当数据流过一层：
1. 实时统计该 batch 激活的 min/max
2. 动态计算 scale 和 zero_point
3. 用这组 scale 完成当前层的量化

### 优缺点

- ✅ **精度高**，因为 scale 完美贴合当前输入
- ✅ 部署简单，不需要校准集
- ❌ 每层都要多做一次 min/max 统计，**推理开销上升**
- ❌ 对 batch size 敏感（batch=1 时统计不稳定）

**适用场景**：精度优先、输入分布极不稳定的场景（大模型文本生成就是典型）。

## 对比一览

| 维度 | 静态量化 | 动态量化 |
|------|---------|---------|
| **scale 确定时机** | 校准阶段离线算 | 推理时实时算 |
| **需要校准集** | ✅ 需要 500~1000 条 | ❌ 不需要 |
| **推理开销** | 零额外开销 | 每层多一次统计 |
| **精度** | 中等（依赖校准质量） | 高 |
| **对输入分布变化** | 敏感 | 鲁棒 |
| **典型场景** | CV 部署、边缘推理 | LLM 推理、动态输入 |
| **配套 PTQ 方法** | KL/MSE 校准、SmoothQuant | GPTQ/AWQ 的激活侧 |

## LLM 场景的实际选择

大模型推理里，激活量化几乎都是**动态**或**半动态**（per-token 动态）：

- **W-only 量化（AWQ/GPTQ INT4）**：激活保持 FP16，不做量化，压根没这个问题
- **W8A8（SmoothQuant）**：激活走 per-token 动态量化，每个 token 一组 scale
- **FP8（H100/H200 推理）**：激活走 per-tensor 或 per-token 动态 FP8
- **NVFP4**：激活走 per-block 动态量化 + FP8 块 scale

**为什么大模型不用静态？** —— 输入分布太不稳定，校准集根本覆盖不完，静态量化的精度损失不可接受。而且现代 GPU 上，per-token 的 min/max 统计开销相对整个矩阵乘可以忽略。
